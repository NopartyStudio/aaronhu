## 一、先把问题说清楚

### 1.1 单源 vs 多源

| | 单源最短路（SSSP） | 多源最短路（APSP） |
|---|---|---|
| 问什么 | 一个起点到其它点 | 任意两点之间 |
| 典型问法 | 甲地到乙地最短 | 7 个城市两两之间的距离 |
| 算法 | Dijkstra / Bellman-Ford / SPFA | Floyd |
| 复杂度 | 接近 O(m log n) | O(n³)，n 大就死 |

课件一开始用同一张"甲地—乙地图"提这两个问题（图上标注的数是公里数），正好说明：**同一张图，问法不同，算法不同**。

### 1.2 几个必须搞清楚的前提

- **有向还是无向**：无向边 = 两条方向相反的有向边。
- **边权**：可以有 0，可以有负数。**有负数时 Dijkstra 直接作废**（后面有反例）。
- **重边**：两点之间多条边 → 只保留权值最小的那条。
- **自环**：正权自环永远不选，可以不管；负权自环 = 负环。
- **什么时候"最短路不存在"**：
  1. 起点到不了（距离还是 ∞）；
  2. 路径上有**负环**，可以无限绕圈把距离刷到 −∞。

### 1.3 规模决定算法

| n（点数） | m（边数） | 首选 |
|---|---|---|
| ≤ 1000 | 很密（≈ n²） | 朴素 Dijkstra O(n²) |
| 1e5 | 稀疏 | 堆优化 Dijkstra |
| 1e5 | 稀疏 + 有负边 | SPFA（祈祷不被卡）/ Bellman-Ford |
| ≤ 400~500 | 任意 | Floyd |

## 二、五个算法，一张图定位

![五个算法的位置](/assets/blog/shortest-path-02.svg)

**选型口诀**

1. 有负权边吗？没有 → **Dijkstra**；有 → **SPFA / Bellman-Ford**。
2. 要求所有点对吗？要求 → **Floyd**（n 小才行）；不要求 → 单源算法更快。
3. 题目说"最多经过 k 条边" → **Bellman-Ford 的第 k 轮**，别的算法都不好使。

## 三、松弛：所有算法的同一颗心脏

![松弛操作](/assets/blog/shortest-path-03.svg)

不管哪种算法，干的都是同一件事：

```cpp
if (d[v] > d[u] + w)      // 从 u 绕过去更近？
    d[v] = d[u] + w;      // 那就改小
```

这条语句叫**松弛（relax）**。所有边都松弛到不能再改时，全图满足**三角不等式**：

```
d[v] ≤ d[u] + w(u, v)     对每条边都成立
```

> 为什么叫"三角"？跟三角形两边之和大于第三边是一个意思：从起点直接到 v，不会比"先到 u 再到 v"更远。

**五个算法的区别只有一件事：松弛的顺序。**

| 算法 | 松弛顺序 |
|---|---|
| Dijkstra | 每次挑当前最近的点，松弛它的出边 |
| Bellman-Ford | 每轮把所有边**从头到尾**松弛一遍，共 n 轮 |
| SPFA | 只松弛"距离刚变小的点"的出边 |
| Floyd | 按"允许经过哪个中转点"分层，把整个矩阵松弛一遍 |

## 四、Dijkstra（朴素）：两个集合，两个步骤

### 4.1 思想

把点分成两个集合：

- **S**：已经确定最短距离的点（"定案"）；
- **U**：还没确定的点。

每一步：

1. 在 U 里找 `d` 最小的点 t；
2. 把 t 挪进 S（**从此它的 d 不再改变**）；
3. 用 t 松弛它的所有出边。

循环 n 次，所有点就都定案了。

**为什么敢"定案"？** 因为边权都 ≥ 0。假设 t 的当前 d 是 U 里最小的，那么任何"绕路"方案都要先经过 U 里某个点 x，而 d[x] ≥ d[t]，再加上非负的边权，绕过去只会更远。所以 t 现在这个值一定就是最终答案。

> 这个"非负"条件就是 Dijkstra 的命门，负权边一出现，上面的推理立刻崩（见第六节）。

### 4.2 手推一遍（重点，考试常考）

![Dijkstra 逐步演示](/assets/blog/shortest-path-04.svg)

图里 7 个点（0~6），12 条无向边，起点是 0。跟着 8 帧走一遍：

| 轮次 | 选中的点 | d[] 变化 | 说明 |
|---|---|---|---|
| ① 初始 | — | 0, 4, 6, 6, ∞, ∞, ∞ | 只填与 0 直连的边 |
| ② | ① d=4 | d[2]=5, d[4]=11 | 4+1=5，4+7=11 |
| ③ | ② d=5 | d[5]=9 | 5+4=9；5+2=7 > 6，d[3] 不变 |
| ④ | ③ d=6 | 无变化 | 6+5=11 > 9 |
| ⑤ | ⑤ d=9 | d[4]=10, d[6]=17 | 9+1=10 比 11 好！9+8=17 |
| ⑥ | ④ d=10 | d[6]=16 | 10+6=16 |
| ⑦ | ⑥ d=16 | 无变化 | 全部定案 |

**最终**：`d = [0, 4, 5, 6, 10, 9, 16]`

两个容易被忽略的点：

- 第 ⑤ 轮，点 ④ 的 d 从 11 变成 10 —— 说明**定案前**一个点可以被改很多次；
- 第 ③、④ 轮"没有变化"也是正常的一轮，算法照样走完 n 次。

### 4.3 代码（邻接矩阵版）

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 510, INF = 0x3f3f3f3f;

int n, m;
int g[N][N];      // 邻接矩阵：g[u][v] = u→v 的边权
int d[N];         // d[i] = 起点到 i 的当前最短距离
bool vis[N];      // true = 已经进 S（定案）

void dijkstra(int s) {
    memset(d, 0x3f, sizeof d);
    d[s] = 0;

    for (int i = 1; i <= n; i++) {          // 循环 n 次，每次定案一个点
        // 1. 在 U 里找 d 最小的点 t
        int t = -1;
        for (int j = 1; j <= n; j++)
            if (!vis[j] && (t == -1 || d[j] < d[t])) t = j;

        if (t == -1 || d[t] == INF) return; // 剩下的点都到不了
        vis[t] = true;                      // 2. t 进 S

        // 3. 用 t 松弛它的出边
        for (int v = 1; v <= n; v++)
            if (!vis[v] && g[t][v] < INF)
                d[v] = min(d[v], d[t] + g[t][v]);
    }
}

int main() {
    cin >> n >> m;
    memset(g, 0x3f, sizeof g);              // 先全部设成"没有边"
    for (int i = 0; i < m; i++) {
        int u, v, w;
        cin >> u >> v >> w;
        g[u][v] = min(g[u][v], w);          // 重边只留最小的
        // g[v][u] = min(g[v][u], w);       // 无向图要加这一行
    }
    dijkstra(1);
    cout << (d[n] == INF ? -1 : d[n]);
}
```

### 4.4 复杂度为什么是 O(n²)

- 外层循环 n 次；
- 里面两个 O(n) 的循环：找最小 + 更新邻居；
- 合起来 **O(n²)**，跟 m 无关。

所以它**适合稠密图**（m ≈ n²），n ≤ 1000 都能过。

## 五、Dijkstra 堆优化：把"找最小"交给堆

### 5.1 朴素版慢在哪

每轮都要扫一遍所有点找最小的，这一步是 O(n)。而点被更新后其实"排个队"就行 —— 用**小根堆（优先队列）**可以把找最小降到 O(log n)。

![堆优化](/assets/blog/shortest-path-05.svg)

### 5.2 懒删除：堆里的旧记录

`priority_queue` **不能修改元素**，只能再 push 一个新的。于是同一个点可能同时有 `(17,6)` 和 `(16,6)` 两条记录。

处理办法很简单：

```cpp
if (vis[u]) continue;   // 这个点早就定案了，这是一条旧记录，扔掉
```

反过来，如果弹出的点还没定案，那它一定是当前堆里最小的，直接定案。

### 5.3 代码（邻接表 + 小根堆）

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 100010, INF = 0x3f3f3f3f;

struct Edge { int v, w; };

int n, m;
vector<Edge> e[N];
int d[N];
bool vis[N];

void dijkstra(int s) {
    memset(d, 0x3f, sizeof d);
    d[s] = 0;

    // 小根堆：pair 先比 first，所以 (距离, 点) 会自动让距离小的在堆顶
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> q;
    q.push({0, s});

    while (!q.empty()) {
        int du = q.top().first, u = q.top().second;
        q.pop();

        if (vis[u]) continue;       // 旧记录，跳过
        vis[u] = true;              // 定案

        for (auto ed : e[u]) {
            int v = ed.v, w = ed.w;
            if (d[v] > du + w) {
                d[v] = du + w;
                q.push({d[v], v});  // 入堆的是新距离，不是边权
            }
        }
    }
}
```

> 课件里用的是"大根堆 + 存负距离" `priority_queue<pair<int,int>> q; q.push({-d[v], v});`
> 两种写法完全等价，`greater<>` 更好读，负距离版更短的代码。

### 5.4 复杂度

- 每条边最多导致一次 push，共 O(m) 次入堆，每次 O(log m)；
- 每次出堆 O(log m)，最多 O(m) 次；
- 合计 **O((n + m) log m)**，稀疏图下常写成 **O(m log n)**。

n = 1e5、m = 2e5 的题，这个量级随便过；朴素 O(n²) 就爆了。

> 同目录下的 `dijkstra-visualizer.html` 是一个可交互的优先队列模拟器，想看看堆里到底怎么进出，可以直接打开点点看。

## 六、负权边为什么能杀死 Dijkstra

![负权边反例](/assets/blog/shortest-path-06.svg)

课件给的图：`1→2(1)`、`1→3(3)`、`2→4(1)`、`3→4(−3)`、`4→5(1)`。

Dijkstra 会这么走：

| 轮次 | 选中的点 | d 数组 | 发生了什么 |
|---|---|---|---|
| ① | 1 (d=0) | 0, 1, 3, ∞, ∞ | 松弛 1→2、1→3 |
| ② | 2 (d=1) | 0, 1, 3, **2**, ∞ | 松弛 2→4，d[4]=2 |
| ③ | 4 (d=2) | 0, 1, 3, 2, **3** | 4 定案！再松弛 4→5 |
| ④ | 3 (d=3) | 0, 1, 3, 2, 3 | 想改 4：3+(−3)=0 < 2，但 4 已在 S 里，**改不了** |

答案 3，可真正的最短路是 `1→3→4→5 = 3−3+1 = 1`。

**根因**：Dijkstra 的每一步都在赌"U 里 d 最小的点已经最终确定"。负权边让"绕远路"变得比"直达"更近，这个赌局直接输掉。

**所以：只要边权可能是负数，就不要用 Dijkstra。**

## 七、Bellman-Ford：不挑点，全部边都松弛

### 7.1 思想

不再挑"最近的点"，改成**每轮把 m 条边全部松弛一遍**，做 n 轮。

它的语义非常干净：

> **第 k 轮结束后，d[v] 就是"最多走 k 条边"时 v 的最短距离。**

所以：

- 最短路最多 n−1 条边 → n−1 轮后一定收敛；
- 第 n 轮还能改小 → 说明存在**负环**（因为正常最短路不会超过 n−1 条边）。

![Bellman-Ford](/assets/blog/shortest-path-07.svg)

上面例子里：`1→2(1)`、`2→3(1)`、`1→3(3)`。

| | d[1] | d[2] | d[3] | 含义 |
|---|---|---|---|---|
| 初始 | 0 | ∞ | ∞ | 只知道自己 |
| 第 1 轮 | 0 | 1 | 3 | 最多 1 条边：d[3] 只能取 3 |
| 第 2 轮 | 0 | 1 | **2** | 最多 2 条边：1+1=2 更好 |
| 第 3 轮 | 0 | 1 | 2 | 不再变化 → 收敛 |

### 7.2 为什么必须 backup

看第 1 轮：如果**不备份**，先松弛 `1→2` 把 d[2] 改成 1，再松弛 `2→3` 时就会用这个新的 d[2] 把 d[3] 改成 2 —— **一轮里走了两条边**。

这样"第 k 轮 = 最多 k 条边"的性质就没了，n 轮判负环的结论也就不可靠了。

```cpp
memcpy(backup, d, sizeof d);   // 本轮只读 backup，写 d
```

### 7.3 代码（边表存图）

```cpp
const int N = 510, M = 10010, INF = 0x3f3f3f3f;

struct Edge { int u, v, w; } e[M];
int d[N], backup[N];

// 返回 true 表示没有负环；false 表示存在负环
bool bellman_ford(int s) {
    memset(d, 0x3f, sizeof d);
    d[s] = 0;

    for (int k = 1; k <= n; k++) {
        memcpy(backup, d, sizeof d);            // 备份上一轮
        for (int i = 1; i <= m; i++) {
            int u = e[i].u, v = e[i].v, w = e[i].w;
            if (backup[u] < INF && d[v] > backup[u] + w)
                d[v] = backup[u] + w;           // 只读 backup
        }
    }

    // 再多试一轮：还能变小 → 有负环
    for (int i = 1; i <= m; i++) {
        int u = e[i].u, v = e[i].v, w = e[i].w;
        if (d[u] < INF && d[v] > d[u] + w) return false;
    }
    return true;
}
```

复杂度 **O(nm)**，n 和 m 都上千就危险了。

> **题型提醒**：题目如果说"最多经过 k 条边"，就把外层循环改成 k 轮，别用 n 轮 —— 这正是 Bellman-Ford 唯一不可替代的地方。

## 八、SPFA：Bellman-Ford 的队列优化

### 8.1 思路

BF 慢在"每轮把 m 条边全扫一遍"，但一轮里真正会让别人变小的，只有那些**刚刚变小的点**。

所以：开一个队列，谁的距离被改小了，谁就进队；每次取出队头，松弛它的出边。

![SPFA 队列演示](/assets/blog/shortest-path-08.svg)

注意第 ④ 步：3 把 d[4] 从 2 改成 0，**4 已经在队列里了，就不要再 push 一次**（靠 `inq[]` 判断）。

### 8.2 代码

```cpp
int d[N], cnt[N];
bool inq[N];

bool spfa(int s) {
    memset(d, 0x3f, sizeof d);
    queue<int> q;
    d[s] = 0;
    q.push(s);
    inq[s] = true;

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        inq[u] = false;                     // 出队了，以后还能再进来

        for (auto ed : e[u]) {
            int v = ed.v, w = ed.w;
            if (d[v] > d[u] + w) {
                d[v] = d[u] + w;
                cnt[v] = cnt[u] + 1;        // 到 v 用了几条边
                if (cnt[v] >= n) return false;   // 有负环
                if (!inq[v]) {              // 不在队列里才入队
                    q.push(v);
                    inq[v] = true;
                }
            }
        }
    }
    return true;
}
```

### 8.3 判负环

![负环](/assets/blog/shortest-path-09.svg)

**负环**：环上边权之和 < 0。每绕一圈距离就更小，最短路不存在。

程序里怎么看出来的？用 `cnt[x]` 记"当前最短路用了几条边"：

- 每次 `d[v]` 被改小，就 `cnt[v] = cnt[u] + 1`；
- 如果某次 `cnt[v] ≥ n`：n 个点的路径上必有重复点（**抽屉原理**），也就是说路径里有环；
- 这个环让距离还能继续变小 → 它一定是**负环**。

### 8.4 复杂度与风险

- 一般情况 **O(m)** 左右，随机数据飞快；
- 最坏 **O(nm)**，跟 BF 一样；
- 出题人可以专门造"菊花图 + 网格图"卡 SPFA，所以**能写 Dijkstra 就别写 SPFA**；
- 小优化（了解即可）：`SLF`（入队时若比队头小就插到队头）、`LLL`。

## 九、Floyd：一次算完所有点对

### 9.1 思想：把"允许经过哪些中转点"当成 DP 的一层

![Floyd](/assets/blog/shortest-path-10.svg)

从 i 到 j，只有两种可能：

1. 直达，不经过任何中转点；
2. 从 i 到 k，再从 k 到 j。

于是定义：

```
f[k][i][j] = 只允许用 1..k 这些点当中转时，i 到 j 的最短距离
```

转移：

```
f[k][i][j] = min( f[k-1][i][j],  f[k-1][i][k] + f[k-1][k][j] )
              不经过 k 的        经过 k 的
```

降维成二维（跟背包的滚动数组一个道理）：

```cpp
f[i][j] = min(f[i][j], f[i][k] + f[k][j]);
```

### 9.2 代码

```cpp
const int N = 410, INF = 0x3f3f3f3f;
int d[N][N];

// 初始化
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= n; j++)
        d[i][j] = (i == j ? 0 : INF);

// 读边
for (int i = 1; i <= m; i++) {
    int u, v, w; cin >> u >> v >> w;
    d[u][v] = min(d[u][v], w);
    // d[v][u] = min(d[v][u], w);   // 无向图
}

// 三重循环：k 必须在最外层！
for (int k = 1; k <= n; k++)
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            if (d[i][k] < INF && d[k][j] < INF)   // 防溢出
                d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
```

### 9.3 三个坑

1. **k 必须写最外层**。写成 `i-j-k` 就变成"只允许一条边中转"，结果错误。
2. **INF 相加会溢出**。`0x3f3f3f3f + 0x3f3f3f3f` 还在 int 范围内，但如果用 `INT_MAX` 就废了；加个 `if` 判断最稳。
3. **有序号从 0 开始的题**，数组别越界。

复杂度 **O(n³)**，n = 400 约 6.4e7，勉强过；n = 1000 就别想了。

## 十、横向对比

| 算法 | 解决 | 负权边 | 判负环 | 时间复杂度 | 空间 | 典型场景 |
|---|---|---|---|---|---|---|
| Dijkstra 朴素 | 单源 | ✗ | ✗ | O(n²) | O(n²) | 稠密图，n ≤ 1000 |
| Dijkstra 堆优化 | 单源 | ✗ | ✗ | O((n+m) log m) | O(n+m) | 稀疏图，**首选** |
| Bellman-Ford | 单源 | ✓ | ✓ | O(nm) | O(n+m) | 限制边数 k 条 |
| SPFA | 单源 | ✓ | ✓ | 平均 O(m)，最坏 O(nm) | O(n+m) | 有负边、随机数据 |
| Floyd | 多源 | ✓ | ✓ | O(n³) | O(n²) | n ≤ 400 全源 |

### 判断流程

```
有负权边吗？
├─ 没有 ──> n ≤ 1000 且很稠密？
│            ├─ 是 ──> 朴素 Dijkstra O(n²)
│            └─ 否 ──> 堆优化 Dijkstra
└─ 有 ────> 要求所有点对？
             ├─ 是 且 n 小 ──> Floyd
             ├─ 限制最多 k 条边 ──> Bellman-Ford（k 轮）
             └─ 否 ──> SPFA（注意可能被卡）
```

### 易错清单（考前扫一眼）

1. `INF` 用 `0x3f3f3f3f`，别用 `INT_MAX`，否则 `INF + w` 溢出变负数。
2. 松弛前判断 `d[u] < INF`，不然无穷大会被"更新"。
3. 重边要取 `min`，自环要忽略（负自环除外）。
4. 堆优化的 `vis[]` 不能省，否则旧记录反复处理，慢到 TLE。
5. 入堆的是 `(d[v], v)`，**不是** `(w, v)`。
6. BF 忘记 `backup`，"第 k 轮 = k 条边"就废了。
7. SPFA 出队后忘记 `inq[x] = false`，那个点以后再也进不来。
8. Floyd 的 `k` 写到最内层，答案会错但样例可能过 —— 必须背下来：**k 在外**。
9. 多组测试数据：`g[][]`、`d[]`、`vis[]`、`e[]` 全部要清空。
10. 要输出路径时另开 `pre[]`，在松弛成功时记 `pre[v] = u`。
11. 无向图存边要存两次；Floyd 初始化要对称。
12. 起点终点的特判：`s == t` 时答案是 0。

6. 最外层。写成 i、j、k 的顺序，就只允许"一条边当中间段"，无法组合多个中转点，结果偏大。
7. ① 堆优化 Dijkstra；② Floyd；③ Bellman-Ford，跑 k=3 轮。

## 十二、再往前的几个方向（有余力再看）

| 方向 | 大致做法 |
|---|---|
| 最短路计数 | 松弛成功时 `cnt[v] = cnt[u]`，相等时 `cnt[v] += cnt[u]` |
| 最短路径树 | 松弛成功时记 `pre[v] = u`，倒着回溯 |
| 次短路 | 每个点存"最短路 / 次短路"两个值，一起松弛 |
| 分层图最短路 | 把"用了几次免费机会"做成一层，`d[u][k]` 变成二维 |
| 最小环（无向图） | Dijkstra 时把 `d[u] + w + d[v]` 取最小；Floyd 版本在 k 那层之前统计 |
| 传递闭包 | Floyd 把 `min` 换成 `或`，或直接用 `bitset` 加速 |
| 0-1 边权 | 双端队列 BFS（边权只有 0 和 1 时比堆更快） |
