## 一句话理解

并查集维护的是 **"谁和谁是一伙的"** 。

它只回答两个问题：

- `find(x)`：x 属于哪个集合？（返回这个集合的**代表元**）
- `union(x, y)` / `merge(x, y)`：把 x 和 y 所在的两个集合合并成一个。

它**不关心**两点之间怎么走、路径长什么样，只关心**在不在同一个集合**。所以它比图论里的 BFS/DFS 判断连通快得多。

> 典型用途：动态连通性、Kruskal 最小生成树、判断无向图加边是否成环、"朋友的朋友是朋友"、"敌人的敌人是朋友"。

---

## 核心思想：用一棵树代表一个集合

每个集合选一个**代表元**（叫它"老大"），整个集合组织成一棵树，**树根就是老大**。

用一个数组 `fa[]` 存父子关系：

```
fa[x] = x 的父结点编号
```

根结点特殊：**它自己指向自己**。

```
fa[root] = root
```

于是：

- **判断 x 和 y 是否同一集合** → `find(x) == find(y)`，即"两个老大是不是同一个"。
- **合并两个集合** → 让一个老大认另一个老大当爹：`fa[rootA] = rootB`。

关键点：**数组里存的不是"集合编号"，而是一条指向父结点的边。** 这就是并查集能"动态合并"的原因——合并只需要改一个指针。

---

## 初始化

```cpp
int fa[N];

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i;      // 一开始每个人自己是一个集合，自己就是自己的老大
    }
}
```

> 易错：一定要初始化。全局数组默认是 0，如果不写 `fa[i] = i`，`find` 会直接死循环或算错。

---

## 朴素写法（不优化）

### find：一路往上爬到根

```cpp
int find_root(int x) {
    while (fa[x] != x) {   // 只要不是根，就往上走
        x = fa[x];
    }
    return x;
}
```

### union：把一个根挂到另一个根下面

```cpp
void merge(int x, int y) {
    int rx = find_root(x);
    int ry = find_root(y);
    if (rx == ry) return;  // 本来就一家，不用合
    fa[rx] = ry;           // 让 rx 认 ry 当爹
}
```

### 复杂度：最坏会退化成一条链

如果每次合并都恰好"把长链接到短链下面"，树会变成一条直线：

```
merge(1,2) → 1←2
merge(2,3) → 1←2←3
merge(3,4) → 1←2←3←4
...
```

这时候 `find(n)` 要走 `n` 步，单次 **O(n)**。

- `m` 次操作、`n` 个元素：最坏 **O(nm)**。
- 这就是为什么要优化。

---

## 优化一：路径压缩

你贴的这段就是**路径压缩**（Path Compression）：

```cpp
int find_root(int x) {
    if (fa[x] == x) return x;          // 自己是根，直接返回
    return fa[x] = find_root(fa[x]);   // 先递归找到根，再把自己的爹改成根
}
```

### 逐行拆开看

```
find_root(x)
  ├─ fa[x] == x ?  → 是根，返回 x
  └─ 否则：
       t = find_root(fa[x])   // 递归找到真正的根
       fa[x] = t              // 把 x 的父指针直接改成根（这就是"压缩"）
       return t
```

`return fa[x] = find_root(fa[x]);` 这一行做了两件事：

1. `find_root(fa[x])` 递归求出根 `t`；
2. `fa[x] = t` 把 x 直接挂到根下面；
3. 赋值表达式的值是 `t`，所以顺便 `return t`。

### 压缩是怎么发生的

递归是"先往下走、再往回弹"的。往回弹的时候，**路径上的每一个结点都执行一次 `fa[u] = 根`**，于是整条路径被拍平：

```
压缩前：        压缩后：
    1               1
    |             / | \
    2            2  3  4
    |
    3
    |
    4
```

`find_root(4)` 之后，4、3、2 全都直接指向 1。下次再查它们，**一步到位**。

> 注意：路径压缩只改**这次查找经过的那条路径**上的点，不会去动别的分支。

### 只看路径压缩的复杂度

- 单次最坏仍然是 O(n)（第一次查一条长链）。
- 但**均摊**是 **O(log n)**：因为每次走的冤枉路，都被"压缩"存起来给以后用了。Tarjan 用势能分析证明了这一点。
- 空间：O(n)。

---

## 优化二：按大小 / 按秩合并

路径压缩解决"查得慢"，**按大小合并**（Union by Size）解决"树长得太高"。

思路很朴素：**小集合挂到大集合下面**，别让大树越长越高。

```cpp
int sz[N];   // sz[root] = 这个集合的元素个数（只对根有意义）

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        sz[i] = 1;
    }
}

void merge(int x, int y) {
    int rx = find_root(x);
    int ry = find_root(y);
    if (rx == ry) return;

    if (sz[rx] < sz[ry]) swap(rx, ry);  // 保证 rx 是大的那个
    fa[ry] = rx;                        // 小的挂到大的下面
    sz[rx] += sz[ry];                   // 合并后大小相加
}
```

### 为什么树高能压到 O(log n)

一个结点每被"往上挪一层"，它所在集合的大小**至少翻倍**（因为它原来在小集合里，挂过去之后至少和另一个不更小的集合合并）。

集合大小最多是 n，所以一个结点最多被挪 `log₂ n` 次。

→ **树高 ≤ O(log n)**，单次 `find` 最坏 **O(log n)**。

> 用"秩"（rank，树高的上界）代替"大小"也行，效果一样，叫 Union by Rank。日常写 `sz` 更直观。

### 一个常见误解

**路径压缩之后，`sz` / `rank` 不需要维护成"真实树高"。**

- `sz` 仍然是准确的集合大小，合并时照常相加；
- 但 `rank` 只能当"上界"，压缩后实际高度会变小，**不用回头去改**。这不影响正确性，也不影响 O(α(n)) 的结论。

---

## 两个一起用：O(α(n))

路径压缩 + 按大小合并，就是标准并查集：

```cpp
int find_root(int x) {
    if (fa[x] == x) return x;
    return fa[x] = find_root(fa[x]);
}
```

均摊复杂度 **O(α(n))**，其中 `α` 是**反阿克曼函数**。

这个函数增长慢到离谱：


| n | α(n) |
| ---------- | ----- |
| 10 | ≤ 3 |
| 10⁹ | ≤ 4 |
| 任何能存进计算机的数 | 不超过 5 |


所以实际做题时，**可以直接把它当 O(1)**。

---

## 复杂度总表


| 写法 | 单次 find | m 次操作 | 树高 |
| -------- | ----------- | ------------- | ----------- |
| 朴素 | O(n) 最坏 | O(nm) | 可能退化成链，O(n) |
| 只路径压缩 | O(log n) 均摊 | O(m log n) | 均摊很短 |
| 只按大小/秩合并 | O(log n) 最坏 | O(m log n) | ≤ log₂ n |
| **两者都用** | **O(α(n))** | **O(m α(n))** | 极小 |


空间都是 **O(n)**（`fa` + `sz` 两个数组）。

## 完整模板（可直接背）

```cpp
#include <iostream>
using namespace std;

const int N = 100010;

int fa[N], sz[N];

void init(int n) {
    for (int i = 1; i <= n; i++) {
        fa[i] = i;
        sz[i] = 1;
    }
}

// 递归版：短小，但链特别长时可能爆栈
int find_root(int x) {
    if (fa[x] == x) return x;
    return fa[x] = find_root(fa[x]);
}

// 迭代版：n 很大（比如 1e6 以上）时更安全
int find_root_iter(int x) {
    int r = x;
    while (fa[r] != r) r = fa[r];   // 第一遍：找根

    while (x != r) {                 // 第二遍：路径上每个点直接连到根
        int nxt = fa[x];
        fa[x] = r;
        x = nxt;
    }
    return r;
}

void merge(int x, int y) {
    int rx = find_root(x);
    int ry = find_root(y);
    if (rx == ry) return;

    if (sz[rx] < sz[ry]) swap(rx, ry);
    fa[ry] = rx;
    sz[rx] += sz[ry];
}

int main() {
    int n, m;
    cin >> n >> m;
    init(n);

    while (m--) {
        int op, x, y;
        cin >> op >> x >> y;
        if (op == 1) {
            merge(x, y);
        } else {
            cout << (find_root(x) == find_root(y) ? "Y" : "N") << '\n';
        }
    }
    return 0;
}
```

> 例：洛谷 **P3367【模板】并查集** 就是这道题的格式。可以先拿它验证模板。

## 易错点

1. **忘记初始化**：`fa[i] = i` 是并查集的命根子。
2. **union 要比较根，不是比较原结点**：`fa[x] = y` 是错的，必须先 `find`。
3. `**fa[x] == x` 不等于"x 是根"**——它确实表示是根，但**判断连通必须比较 `find(x)` 和 `find(y)`**，不能直接比 `x`、`y`。
4. **递归爆栈**：`find` 递归深度最坏是树高。路径压缩后一般没事，但数据极端（先造一条 `n = 10⁶` 的链再查）时，用迭代版更稳。
5. `**sz` 只在根上更新**：`sz[rx] += sz[ry]` 之后，`ry` 的 `sz` 就作废了，别再读它。
6. **路径压缩不能让并查集支持"删除"或"分裂"**：它只能合并，不能拆。要拆得用别的结构（比如离线倒序、可撤销并查集）。
7. **多组数据要重新 `init`**：上一组的 `fa` 不清空，下一组直接错。

## 进阶：带权并查集（了解即可）

普通并查集只记"谁是爹"。带权并查集在边上再存一个**权值**，表示"我和我爹的关系"，比如：

- 距离 / 偏移量（`fa[x]` 到 `x` 的差）
- 敌对关系（0 = 同类，1 = 异类）

查找时要把一路的权值**累加**起来，合并时要**算出补偿量**，比普通并查集多一个 `d[]` 数组和一点推导。

经典题：

- 洛谷 **P2024 [NOI2001] 食物链**（三类关系，模 3）
- 洛谷 **P1525 [NOIP2010] 关押罪犯**（敌人合并，也可二分图）

> 建议先把普通并查集写熟，再碰带权。

## 一句话总结

**并查集 = 每个集合一棵树 + 只改父指针的合并。**
**路径压缩管"查得快"，按大小合并管"树不高"，两个一起用就是 O(α(n)) ≈ O(1)。**
