## 一、问题是什么

给一个 **n 个点、m 条边的连通无向图**，每条边有权值。选出 **n − 1 条边**，把所有点连成一片，并且**总权值最小**。

这 n − 1 条边构成的结构就是**最小生成树**（Minimum Spanning Tree，MST）。

> 生活版：几个城市之间修路，要求任意两个城市都能到达，且总造价最低。修哪些路？

三个前提：

- 图必须**连通**，否则没有生成树；
- 只适用于**无向图**；
- 边权可以是负数，算法照样成立。

---

## 二、核心思想：从一个点开始"长大"

Prim 的思路非常像"滚雪球"：

1. 随便选一个点，放进"已选集合" S；
2. 每次从**连接 S 和 S 外**的所有边里，挑**权值最小**的那条；
3. 把这条边和它外面的点拉进 S；
4. 重复，直到 S 里有 n 个点。

一句话：**每次把离当前树最近的点拉进来。**

这里说的"距离"不是到起点的路径长度，而是**这个点到已选集合的所有边里最小的那一条的权值**。

```
d[v] = min{ w(u, v) | u 已经在树里 }
```

> 这是和 Dijkstra 最容易混的地方，后面单独对比。

---

## 三、为什么这样贪心是对的（了解）

用**切割性质**（cut property）说明：

把点集分成两半：已选的 S 和未选的 T。横跨 S / T 的边叫"割边"。

> **任意一种切法下，权值最小的割边，一定属于某棵最小生成树。**

Prim 每一步选的，恰好就是当前 (S, T) 这个切法下的最小割边。所以这条边是"安全"的，选它不会把最优解弄丢。

如果某棵 MST 不含这条最小割边 e，把 e 加进去会形成一个环；环上一定还有另一条横跨 S / T 的边 e′。因为 e 是最小割边，所以 `w(e) ≤ w(e')`，用 e 换掉 e′ 之后总权不会变大，仍然是最小生成树。矛盾。

## 四、朴素 Prim：O(n²)

每次**扫描所有未访问点**，找 `d[]` 最小的那个，然后更新它的邻居。

```cpp
const int N = 1010, INF = 0x3f3f3f3f;

int n, m;
int g[N][N];      // 邻接矩阵
int d[N];         // d[v] = v 到已选集合的最小边权
bool vis[N];      // 是否已经加入 MST

int prim_naive(int s) {
    fill(d, d + n + 1, INF);
    d[s] = 0;

    int ans = 0;

    for (int i = 1; i <= n; i++) {
        // 1. 找一个未访问、且 d 最小的点
        int u = -1;
        for (int j = 1; j <= n; j++) {
            if (!vis[j] && (u == -1 || d[j] < d[u])) {
                u = j;
            }
        }

        if (u == -1 || d[u] == INF) return -1;  // 图不连通

        // 2. 加入 MST
        vis[u] = true;
        ans += d[u];

        // 3. 用 u 更新邻居
        for (int v = 1; v <= n; v++) {
            if (!vis[v] && g[u][v] < d[v]) {
                d[v] = g[u][v];
            }
        }
    }
    return ans;
}
```

复杂度：

- 外层 n 次，内层两次扫描 n 个点 → **O(n²)**；
- 更新邻居再加 O(m)；
- 总共 **O(n² + m)**，空间 O(n²)。

**适合稠密图**（m 接近 n²），比如 n ≤ 1000 的题。

## 五、Heap-Prim：用优先队列维护"被更新的点"

朴素版慢在"每次都要扫一遍所有点找最小"。用一个**优先队列**就能快速取出最小的 `d`。

### 5.1 课件写法：大根堆 + 存负距离

C++ 的 `priority_queue` **默认是大根堆**。想要"距离最小的在堆顶"，有两个办法：

1. 存 `-d`，让最小的距离变成最大的值，浮到堆顶；
2. 显式指定小根堆比较器（见 5.2）。

课件用的是第 1 种：

```cpp
priority_queue<pair<int, int>> q;  // { -距离, 点 }
```

pair 默认先比较 `first`，所以 `-d` 越大（即 d 越小），越靠堆顶。

### 5.2 课件代码

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 100010, INF = 0x3f3f3f3f;

struct Edge {
    int v, w;
};

int n, m;
vector<Edge> e[N];
int d[N];
bool vis[N];

bool prim(int s) {
    fill(d, d + n + 1, INF);
    d[s] = 0;

    priority_queue<pair<int, int>> q;  // 大根堆，first 存 -距离
    q.push({0, s});

    int ans = 0, cnt = 0;

    while (!q.empty()) {
        int u = q.top().second;
        q.pop();

        if (vis[u]) continue;   // 旧记录，直接跳过

        vis[u] = true;          // 标记 u 已出队（已加入 MST）
        ans += d[u];
        cnt++;

        for (auto ed : e[u]) {
            int v = ed.v, w = ed.w;
            if (d[v] > w) {         // 只与边权比较，不累加
                d[v] = w;
                q.push({-d[v], v}); // 存负距离，小的浮到堆顶
            }
        }
    }

    return cnt == n;   // 连通则 cnt == n
}
```

### 5.3 更常见的写法：显式小根堆

```cpp
priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    greater<pair<int, int>>
> q;   // {距离, 点}，小的在堆顶

q.push({d[s], s});
// 更新时：
q.push({d[v], v});
```

两种写法完全等价，看习惯。**注意别混**：存负距离就配大根堆，存正距离就配 `greater` 小根堆。

## 六、为什么会有"旧记录"（懒删除）

同一个点可能被更新很多次：

```
先通过边权 6 入队 → d[5] = 6
后来通过边权 3 入队 → d[5] = 3
```

但优先队列**不支持修改或删除中间元素**。旧的 `{6, 5}` 只能继续留在堆里。

所以弹出时要判断：

```cpp
if (vis[u]) continue;
```

- 第一次弹出 u 时，`d[u]` 一定是当时最小的，加入 MST；
- 以后再弹出 u（旧记录），`vis[u]` 已为 true，跳过即可。

这叫**懒删除**（lazy deletion）。

> 堆里元素最多 O(m) 个，因为每条边最多触发一次 push。

## 八、复杂度分析

设点数为 n，边数为 m。

### 堆操作次数

- 每条边最多让一个点入队一次 → **最多 O(m) 次 push**；
- 每次 pop 也是 O(m) 次；
- 每次 push / pop 是 **O(log m)**。

所以：

$$
O(m \log m)
$$

空间：

- 邻接表 O(n + m)；
- 堆最坏 O(m)；
- 总共 **O(n + m)**。

### 和朴素版对比


| 写法 | 时间复杂度 | 空间 | 适合 |
| --------- | ---------- | ------------- | -------- |
| 朴素 Prim | O(n² + m) | O(n²)（邻接矩阵） | 稠密图 |
| Heap-Prim | O(m log m) | O(n + m)（邻接表） | 稀疏图、一般情况 |


> 稠密图时 m ≈ n²，`O(m log m)` 反而不如 `O(n²)`，所以有些题会特意用朴素 Prim。

## 九、最容易混的：Prim vs Dijkstra

两个算法代码长得几乎一样，但 `d[]` 的含义**完全不同**。


|  | Prim | Dijkstra |
| --------- | --------------------- | ---------------------------- |
| `d[v]` 含义 | v 到**已选集合**的最小边权 | 起点 s 到 v 的**最短路径长度** |
| 松弛写法 | `d[v] = min(d[v], w)` | `d[v] = min(d[v], d[u] + w)` |
| 干什么用 | 求最小生成树 | 求单源最短路 |
| 是否累加 | **不累加**，只看一条边 | **累加**，要把之前的路径接上 |


记法：

> **Prim 只看"这一条边多长"；Dijkstra 要看"走过来一共多长"。**

## 十、Prim vs Kruskal


|  | Prim | Kruskal |
| ---- | ------------------ | ---------- |
| 扩展方式 | 从一个点往外长 | 按边权从小到大加边 |
| 核心工具 | 优先队列 | 排序 + 并查集 |
| 复杂度 | O(n²) 或 O(m log m) | O(m log m) |
| 适合 | 稠密图、给的是点集 | 稀疏图、给的是边集 |
| 判环 | 不需要 | 用并查集判 |


两个都是贪心，都正确；选哪个主要看图稠密程度和实现顺手程度。

## 十一、易错点

1. **无向图要建双向边**：`e[u].push_back({v,w}); e[v].push_back({u,w});`
2. `**d[]` 要初始化成 INF**，起点 `d[s] = 0`。
3. **弹出后先判 `vis`**，否则旧记录会重复计算。
4. **统计点数 `cnt`**：加入一个点就 `cnt++`，最后 `cnt == n` 才是连通。
5. **大根堆存负距离 / 小根堆存正距离**，两种写法别混用。
6. **松弛是 `d[v] = w`，不是 `d[u] + w`**——这是和 Dijkstra 的分界线。
7. **图不连通时要输出无解**，不能直接返回 `ans`。
8. **多组数据**要清空 `e[]`、`vis[]`、`d[]`。
9. `**int` 溢出**：边权和大规模图的总权值要开 `long long`。
10. **起点随便选**，对结果没有影响。

## 十四、参考答案

> 先自己做一遍，再对照。答案里的"错在哪"比结论更重要。

### 1. `d[v]` 的含义，以及和 Dijkstra 的区别

- Prim：`d[v]` = **v 到已选集合 S 的所有边中，最小的那一条的权值**。它只描述"一条边"。
- Dijkstra：`d[v]` = **起点 s 到 v 的最短路径总长度**。它是把多条边累加起来的。

区别落在松弛那一行：

```cpp
d[v] = min(d[v], w);          // Prim：只看这一条边
d[v] = min(d[v], d[u] + w);   // Dijkstra：把来路接上
```

> 一句话：**Prim 问"这条边多长"，Dijkstra 问"走过来一共多长"。**

---

### 2. 为什么要存 `-d[v]`？直接存 `d[v]` 会怎样？

C++ 的 `priority_queue<pair<int,int>>` **默认是大根堆**，堆顶是 `first` 最大的元素。

- 存 `-d[v]`：`d` 越小 → `-d` 越大 → 越靠堆顶。正好取出"最近的点"。
- 直接存 `d[v]`：堆顶变成 `d` **最大**的点，取出来的是"最远的点"，算法直接错。

如果不想取负，就显式声明小根堆：

```cpp
priority_queue<pair<int,int>, vector<pair<int,int>>, greater<pair<int,int>>> q;
```

两种写法二选一，**不能混**：存负距离配大根堆，存正距离配小根堆。

---

### 3. 为什么同一个点会有多条记录？`vis` 起什么作用？

一个点可能被多次更新：

```
先发现一条权 6 的入边 → d[5] = 6，push {6,5}
后来发现权 3 的入边   → d[5] = 3，push {3,5}
```

但优先队列**不能修改也不能删除**已经进去的元素，所以 `{6,5}` 只能留在堆里。

`vis[u]` 的作用：

- 第一次弹出 u 时，`vis[u]` 还是 false → 加入 MST，标记 true；
- 以后弹出 u 的旧记录时，`vis[u]` 已经是 true → `continue` 跳过。

如果不判断，同一个点会被重复加入、`ans` 被重复累加，答案就错了。

---

### 4. 为什么是 O(m log m)，不是 O(n log n)？

关键在于**堆里装的是"候选边"，不是"点"**。

- 每次发现更小的入边，就 `push` 一次；
- 每条边最多让一个端点入队一次 → push 次数上界是 **O(m)**；
- 每次 push / pop 是 **O(log m)**（堆里有 O(m) 个元素）。

所以总复杂度是 **O(m log m)**。

虽然最终只选 n 个点，但中间可能积累 O(m) 条候选记录，也要付 O(m) 次堆操作的代价。**只加入 n 个点，不代表只做了 n 次操作。**

---

### 5. 什么时候朴素 Prim 比 Heap-Prim 快？

**稠密图**，也就是 `m` 接近 `n²` 的时候。

- 朴素 Prim：O(n²)；
- Heap-Prim：O(m log m) ≈ O(n² log n)。

这时 `n² log n > n²`，朴素版反而更快，而且不用堆、常数更小、代码更短。

典型场景：n ≤ 1000、用邻接矩阵存图的完全图（比如 P1546 这类）。

> 判断口诀：**点多边少用堆，边多点少用朴素。**

---

### 6. 图不连通时，Prim 会怎样？代码靠哪一行发现？

图不连通时，**不存在生成树**，算法只能把起点所在的连通块全部拉进来，然后队列变空，`cnt < n`。

Heap-Prim 靠最后这一行发现：

```cpp
return cnt == n;   // false 表示不连通
```

朴素 Prim 则靠：

```cpp
if (u == -1 || d[u] == INF) return -1;  // 找不到可扩展的点
```

补充：Heap-Prim 里 `d[v] == INF` 的点**不会入堆**，所以不会弹出 INF，只会出现"队列空了但点没选完"。

P3366 的要求是：不连通时输出 `orz`，所以主函数里要判断返回值：

```cpp
if (!prim(1)) cout << "orz";
else          cout << ans;
```

## 十五、一句话总结

**Prim = 从一个点开始，每次贪心地拉进"离当前树最近"的点。**
**Heap-Prim 用优先队列加速找最小值；堆里最多 O(m) 个元素，所以是 O(m log m)。**
**别忘了：`d[v]` 只存一条边的权值，不累加——那是 Dijkstra。**
